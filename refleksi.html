3. Bagian Tersulit & Solusi Penyelesaian

A. Penanganan Buffer Masukan (Input Trapping) di C++ Tanpa Library Eksternal

Tantangan: Penggunaan kombinasi cin >> untuk angka dan getline() untuk nama sering menyebabkan newline (\n) tertinggal di buffer, sehingga program langsung melompati input nama pada transaksi berikutnya tanpa memberi kesempatan pengguna mengetik.

Solusi: Kami menstandarkan seluruh pembacaan input console menggunakan fungsi kustom bacaBaris() berbasis getline(cin, baris) dengan pembersihan spasi (trim) dan konversi bertipe via istringstream. Hal ini menjamin program 100% kebal terhadap crash maupun buffer skipping.

B. Logika Evaluasi Kategori Terbanyak Saat Kondisi Imbang (Tie-Breaking)

Tantangan: Mencari nilai terbesar dari 3 kategori (Mahasiswa, Dosen, Umum) sangat rawan menghasilkan kesimpulan keliru jika hanya menggunakan if-else if sederhana, terutama ketika terjadi seri (misalnya mahasiswa = dosen > umum, atau ketiga kategori sama banyak).

Solusi: Kami menyusun fungsi evaluasiKategoriTerbanyak() dengan struktur evaluasi lengkap: memeriksa kesamaan ketiga kategori terlebih dahulu, kemudian memeriksa kesamaan dua kategori dengan nilai maksimum, baru memutuskan pemenang tunggal jika tidak ada kondisi seri.

C. Hirarki Perhitungan Diskon Bertingkat vs Biaya Tambahan

Tantangan: Memastikan aturan bisnis terpenuhi secara presisi: diskon kelompok 10% harus dihitung setelah diskon Early Bird (bukan dari tarif dasar), sementara sertifikat cetak dan paket makan tidak boleh ikut terpotong diskon sedikit pun.

Solusi: Kami memisahkan tahapan kalkulasi secara berjenjang dalam variabel: tarifSetelahEB = tarif - diskonEB, lalu diskonKlp = tarifSetelahEB * 0.10, dan totalTagihan = (tarifSetelahEB - diskonKlp) + biayaTambahan.

4. Kesalahan & Perbaikan Selama Pengerjaan

No Kesalahan Awal Gejala / Efek Tindakan Koreksi
1 Nilai masukan jumlah anggota kelompok menerima angka 0 dan negatif. Perhitungan diskon kelompok tetap berjalan dan merusak integritas data pendaftaran. Menambahkan loop validasi bacaIntPositif() yang menolak angka ≤ 0 dan mencetak peringatan ramah pengguna.
2 Huruf masukan Y/T peka terhadap huruf kecil (case-sensitive). Pengguna mengetik y kecil ditolak sebagai input tidak valid. Menerapkan toupper() sebelum validasi karakter, sehingga huruf 'y' dan 'Y' diterima sama baiknya.
3 Format angka ribuan sulit dibaca (misal 161000). Tampilan rincian tagihan di terminal kurang profesional dan rawan salah baca saat presentasi. Membuat fungsi utilitas formatRupiah() yang otomatis menyisipkan tanda titik pemisah ribuan (contoh: Rp161.000).
4 Perulangan pembagian dengan nol saat sesi kosong (total peserta = 0). Rumus rata-rata menghasilkan nilai NaN / crash saat program langsung diakhiri. Menambahkan proteksi awal if (totalPeserta == 0) pada fungsi pelaporan akhir Modul B dan integrasi.

5. Pengetahuan Baru yang Diperoleh

  • Pola Validasi Perulangan (Input Guard): Memahami penerapan loop while (true) dengan kondisi pemutus yang menjamin variabel selalu memegang nilai yang sah secara logika dan tipe data sebelum digunakan dalam operasi aritmetika.
  • Siklus Kolaborasi Git/GitHub: Menguasai pembuatan commit bertahap yang bermakna sesuai kaidah *conventional commits* (misal: feat:, docs:, test:), memahami fungsi .gitignore untuk memfilter file binary biner, serta mengelola publikasi web otomatis via GitHub Pages.
  • Korelasi Visual Antar-Artefak: Menyadari pentingnya keselarasan 1:1 antara narasi Algoritma Deskriptif, Pseudocode terstruktur, Diagram Flowchart standar, dan Implementasi C++ nyata.
  • Pentingnya Kesiapan Modifikasi Langsung (Live Coding): Karena telah memahami struktur modular dan fungsi terpisah, kami merasa percaya diri dalam menghadapi *parameter kejutan* saat presentasi di hadapan dosen penguji.

6. Rencana Pengembangan untuk UAS

Mengingat proyek UTS dibatasi pada konsep fundamental algoritma tanpa array dan OOP kompleks, kami merencanakan sejumlah fitur lanjutan yang akan diimplementasikan pada proyek Ujian Akhir Semester (UAS):

Struktur Data Array & Struct / Class

Menyimpan seluruh histori pendaftar ke dalam struct Peserta dan vector<Peserta> sehingga data dapat dicari, diurutkan (sorting berdasarkan tagihan/nama), dan dimodifikasi setelah diinput.

File Handling & Persistensi Data

Mengintegrasikan fitur ekspor dan impor file (CSV/JSON/TXT) menggunakan fstream, sehingga rekapitulasi seminar tidak hilang saat aplikasi ditutup dan dapat dibuka di spreadsheet.

Antarmuka Interaktif / GUI / Web Service

Mengembangkan visualisasi data grafis sederhana atau antarmuka berbasis formulir web interaktif yang langsung terhubung dengan backend C++.
